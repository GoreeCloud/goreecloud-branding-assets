# GoreeCloud Logo Concepts

These files are **approval candidates**, not approved GoreeCloud identity assets. They must not be copied into production applications, websites, social profiles, documentation headers, packages, or release artwork until an explicit approval decision is recorded.

## Design objectives

The concepts intentionally avoid a generic standalone cloud pictogram. GoreeCloud is a privacy-first, self-hosted personal and family cloud platform, so the mark should communicate ownership, infrastructure, connection, continuity, and a recognizable GoreeCloud identity while remaining legible at application-icon and favicon sizes.

The current concepts use a restrained green family consistent with the existing GoreeCloud visual direction. Exact production color tokens remain subject to approval and alignment with Glaze UI.

## Concept A — Infrastructure G

`goreecloud-mark-concept-a.svg`

A bold geometric **G** is the primary identifier. Horizontal infrastructure lanes terminate in nodes, suggesting services, storage, networking, and connected systems. This is the strongest candidate when recognizability at small sizes is the priority.

Characteristics:
- strongest GoreeCloud monogram;
- compact silhouette;
- works well for repository avatars, favicons, launchers, and application chrome;
- infrastructure references remain secondary instead of turning the mark into a network diagram.

## Concept B — Connected Cloud G

`goreecloud-mark-concept-b.svg`

A soft cloud perimeter contains a dark **G** pathway and connection nodes. This is the most literal expression of “GoreeCloud” while still giving the identity a proprietary monogram rather than relying only on a cloud symbol.

Characteristics:
- clearest cloud association;
- softer and more approachable;
- visually compatible with Glaze UI rounded geometry;
- slightly more detailed than Concept A, so very small-size performance requires careful validation.

## Concept C — Modular Platform G

`goreecloud-mark-concept-c.svg`

Rounded modules form a larger platform-like structure around a central control block. The composition references servers, services, applications, storage, and modular infrastructure. It is the most abstract of the three candidates.

Characteristics:
- strongest modular-platform metaphor;
- distinctive grid silhouette;
- naturally adaptable to icon systems and product families;
- less immediately readable as a cloud, intentionally emphasizing GoreeCloud as infrastructure rather than a conventional cloud provider.

## Approval process

After one direction is approved, the selected concept should be refined rather than treating this draft SVG as final artwork. The refinement pass should establish exact geometry, approved color tokens, monochrome variants, light/dark variants, safe area, minimum size, wordmark relationship, accessibility guidance, SVG optimization, raster exports, and application/platform derivatives.

Rejected concepts should remain in `concepts/` as historical design records or be removed only after the approval decision is documented.
